{\large\bfseries Project Proposal: A Compiler from StragglAR Schedules to NCCL Send/Receive Programs}\\[2pt]
Team 31 (Chesterjesters): Wyatt Sell, David Valarezo, Nathnael Tesfaw, Aneesh Naresh\\
Advisor: Arjun Devraj \quad$\cdot$\quad Compute: 2 Perlmutter nodes (8$\times$A100, NCCL over Slingshot)
\end{center}

\textbf{Goal.} StragglAR's synthesizer outputs AllReduce schedules (which rank sends which chunk to whom, per step) in its own text format, but turning a schedule into runnable NCCL code is done by hand. We will build a compiler that parses the schedule into a documented intermediate representation (IR) and generates a C++/CUDA program of grouped \texttt{ncclSend}/\texttt{ncclRecv} calls with local reductions. Success means the generated program runs without deadlock on 8 GPUs across two nodes, gives the same output as \texttt{ncclAllReduce}, and, with the same straggler delay injected into both, finishes faster than \texttt{ncclAllReduce}.

\textbf{Pipeline.} StragglAR schedule (text) $\rightarrow$ parser $\rightarrow$ IR (JSON) $\rightarrow$ code generator $\rightarrow$ NCCL program $\rightarrow$ test harness on Perlmutter.

\textbf{Avoiding blocking.} (1) The IR format is fixed by Oct 29, so the parser and code generator are built against it in parallel. (2) Wyatt hand-writes an $n{=}4$ IR file on Oct 29 so David never waits on the parser. (3) The test harness calls any AllReduce through one function interface, so Aneesh tests NCCL's built-in AllReduce first and swaps in generated code later. (4) Nathnael's launch script is ready by Nov 1, so everyone can run on Perlmutter early.

\textbf{Who does what.} Each person owns one stage end to end, presents it at the midpoint, and makes its poster panel.
